# Доступ к techdesk из интернета

Сначала разверните techdesk в локальной сети ([LAN.md](LAN.md)). Доступ извне нужен сотрудникам
на удаленке, инженеру на выезде или руководителю с телефона.

## Какой вариант выбрать

| | 1. VPN (рекомендуется) | 2. HTTPS через Caddy | 3. Туннель |
|---|---|---|---|
| Как работает | Сотрудник подключается к офисной сети и открывает обычный адрес `http://192.168.1.10:8000` | techdesk опубликован по адресу `https://techdesk.ваш-домен.ru` | Сервис-посредник пробрасывает HTTPS-адрес на сервер |
| Что нужно | Роутер с VPN-сервером (Keenetic, MikroTik, ASUS и т.п.) или WireGuard на сервере | «Белый» IP, домен, проброс портов 80 и 443 | Учетная запись у провайдера туннеля |
| Видно из интернета | Только VPN-порт | Страница входа techdesk | Страница входа techdesk |
| Изменения в techdesk | Не нужны | `make_env.py --domain`, Caddy | `make_env.py --domain` |
| Риск | Минимальный | Подбор паролей, уязвимости — нужна дисциплина обновлений | Как у варианта 2 + зависимость от стороннего сервиса |

**Рекомендация для небольшого офиса — VPN.** Приложение остается внутри сети, а доступ получают
только те, кому выдан VPN-профиль. Если VPN неудобен (много внешних пользователей, телефоны без
VPN-клиента) — вариант 2.

---

## Вариант 1. VPN

1. Включите VPN-сервер на офисном роутере (WireGuard, если роутер умеет; иначе L2TP/IPsec или OpenVPN).
   Инструкцию ищите по модели роутера. Нужен «белый» IP или сервис KeenDNS/DDNS роутера.
2. Создайте отдельный профиль для каждого сотрудника (чтобы можно было отключить одного).
3. Сотрудник ставит VPN-клиент (WireGuard есть для Windows, macOS, Android, iOS), импортирует профиль,
   подключается и открывает тот же адрес, что и в офисе.
4. В techdesk ничего менять не нужно. QR-коды работают, когда телефон подключен к VPN.

## Вариант 2. HTTPS через Caddy

Caddy — веб-сервер, который сам получает и продлевает бесплатный сертификат Let's Encrypt.

### Подготовка (один раз)

1. **«Белый» IP.** Уточните у интернет-провайдера (часто — платная услуга «статический IP»).
2. **Домен.** Купите домен или используйте поддомен существующего сайта компании: `techdesk.компания.ru`.
   В DNS создайте A-запись `techdesk` → белый IP офиса.
3. **Проброс портов на роутере:** TCP 80 и 443 → IP сервера (порт 8000 наружу НЕ пробрасывайте).
4. **Внутри офиса** сотрудники тоже будут ходить на `https://techdesk.компания.ru`. Если из офиса
   адрес не открывается (роутер не умеет «hairpin NAT»), добавьте в DNS роутера запись
   `techdesk.компания.ru → 192.168.1.10`.

### Docker (Linux)

```bash
cd /opt/techdesk
python3 deploy/make_env.py 192.168.1.10 --postgres --domain techdesk.компания.ru
docker compose -f docker-compose.lan.yml -f docker-compose.internet.yml up -d --build
docker compose -f docker-compose.lan.yml exec web python manage.py createsuperuser
```

Нужен Docker Compose 2.24 или новее (`docker compose version`).

### Windows

1. `python deploy\make_env.py 192.168.1.10 --domain techdesk.компания.ru`
   (если `.env` уже есть — переименуйте старый, скрипт его не перезаписывает).
2. Скачайте Caddy для Windows: https://caddyserver.com/download → `caddy_windows_amd64.exe`,
   переименуйте в `caddy.exe` и положите в `deploy\windows\`.
3. В брандмауэре Windows откройте входящие TCP 80 и 443
   (`netsh advfirewall firewall add rule name="techdesk-https" dir=in action=allow protocol=TCP localport=80,443`).
4. Запустите `start.bat`, затем `start_https.bat`. Для автозапуска добавьте оба в Планировщик заданий.

### Что включается в режиме `--domain`

| Настройка | Зачем |
|---|---|
| `DJANGO_HTTPS=1` | Cookie только по HTTPS, заголовок HSTS |
| `BEHIND_PROXY=1` | Реальный IP клиента от Caddy — для блокировки подбора пароля |
| `DJANGO_ADMIN_URL=admin-xxxx/` | Админка не по стандартному адресу `/admin/` |
| `TECHDESK_HOST=127.0.0.1` (Windows) | Приложение доступно только через Caddy |
| `PUBLIC_BASE_URL=https://…` | QR-коды ведут на внешний адрес — работают и с мобильного интернета |

Защита от подбора пароля включена всегда: после 5 неудачных попыток вход для этого логина с этого IP
блокируется на 15 минут (`LOGIN_MAX_FAILURES`, `LOGIN_LOCKOUT_MINUTES`).

## Вариант 3. Туннель

Если белого IP нет, можно использовать сервис туннелей (например, Cloudflare Tunnel): на сервер
ставится агент, сервис выдает HTTPS-адрес. Настройки techdesk — как в варианте 2
(`make_env.py --domain <адрес туннеля>`), но без Caddy: агент туннеля направляется на
`http://127.0.0.1:8000`. Проверьте доступность выбранного сервиса у вашего провайдера и что
условия сервиса подходят компании — трафик проходит через стороннюю инфраструктуру.

## Чек-лист перед открытием доступа извне

- [ ] База чистая, без `seed_demo` (там простые пароли), `SHOW_DEMO_LOGINS=0`
- [ ] У всех пользователей пароли не короче 10 символов, у администратора — уникальный
- [ ] `DJANGO_DEBUG=0`, секретный ключ сгенерирован `make_env.py`
- [ ] Порт 8000 наружу не проброшен, проброшены только 80 и 443 (или только VPN)
- [ ] Резервные копии делаются ежедневно и хранятся вне сервера
- [ ] Раз в месяц: обновление Windows/Linux, `pip install -r requirements.txt --upgrade` на тестовой копии,
      `docker compose pull` для Caddy и PostgreSQL
- [ ] Проверка с телефона через мобильный интернет: вход, создание заявки, QR-код
