# Развертывание techdesk в локальной сети офиса

Сервер — один компьютер в офисе, который включен в рабочее время. Сотрудники открывают
techdesk в браузере по адресу вида `http://192.168.1.10:8000`. Интернет для работы не нужен.

```
[ПК сотрудников, телефоны] --браузер, порт 8000--> [ПК-сервер: techdesk + база]
```

## Что нужно заранее

| Что | Зачем |
|---|---|
| ПК, который не выключают в рабочее время (4 ГБ ОЗУ, 10 ГБ диска достаточно) | На нем работает techdesk |
| Постоянный IP этого ПК | Иначе адрес сайта и QR-коды «сломаются» после перезагрузки роутера |
| Python 3.12+ (вариант A) или Docker (вариант B) | Django 6 не работает на Python 3.11 и ниже |

**Постоянный IP.** В роутере найдите раздел DHCP → «Резервирование адресов» (Address Reservation)
и закрепите IP за MAC-адресом ПК-сервера. Если доступа к роутеру нет — попросите того, кто
его настраивал. Узнать текущий IP: `ipconfig` (Windows) или `ip a` (Linux).

## Вариант A. Windows-ПК (рекомендуется для старта)

База — SQLite (один файл `db.sqlite3`), для офиса до ~50 человек этого достаточно.

1. Установите Python 3.12+ с https://www.python.org/downloads/ (отметьте **Add python.exe to PATH**).
2. Скопируйте папку проекта, например в `C:\techdesk`.
3. Запустите `deploy\windows\install.bat` двойным щелчком. Скрипт:
   создаст окружение, установит зависимости, создаст `.env` с IP этого ПК,
   создаст базу и попросит задать логин/пароль администратора.
4. Правой кнопкой по `deploy\windows\open_firewall.bat` → **Запуск от имени администратора**
   (открывает порт 8000 в брандмауэре Windows).
5. Запустите `deploy\windows\start.bat`. В окне будет адрес для сотрудников.
6. С другого компьютера откройте этот адрес — должна появиться страница входа.
7. Автозапуск при включении ПК: `deploy\windows\autostart.bat` от имени администратора.
8. Резервные копии: добавьте `deploy\windows\backup.bat` в Планировщик заданий
   (ежедневно, например в 20:00). Копии — в папке `backups`, храните их еще и вне этого ПК.

## Вариант B. Linux / мини-ПК / сервер (Docker)

База — PostgreSQL в контейнере.

```bash
# Ubuntu/Debian: установить Docker — https://docs.docker.com/engine/install/
cd /opt/techdesk
python3 deploy/make_env.py 192.168.1.10 --postgres   # IP сервера
docker compose -f docker-compose.lan.yml up -d --build
docker compose -f docker-compose.lan.yml exec web python manage.py createsuperuser
```

- Перезапуск после перезагрузки сервера — автоматический (`restart: unless-stopped`).
- Порт в брандмауэре (если включен ufw): `sudo ufw allow from 192.168.0.0/16 to any port 8000`.
- Резервная копия: `deploy/linux/backup.sh`; в cron — `0 20 * * * /opt/techdesk/deploy/linux/backup.sh`.
- Обновление: `git pull && docker compose -f docker-compose.lan.yml up -d --build`.

## Демонстрация руководителю

Для показа удобно заполнить базу демо-данными и показать демо-логины на странице входа:

```bash
python manage.py seed_demo       # Docker: docker compose -f docker-compose.lan.yml exec web python manage.py seed_demo
```

и в `.env` поставить `SHOW_DEMO_LOGINS=1` (перезапустить сервер).
Демо-пользователи: `admin`, `operator`, `engineer`, `manager`, `employee` (пароль — логин + `123`).

**Перед реальной работой** — на чистой базе без `seed_demo` (там простые пароли `admin123` и т.п.)
и с `SHOW_DEMO_LOGINS=0`. Проще всего: удалить `db.sqlite3` и выполнить `python manage.py migrate`
и `createsuperuser` заново.

## Пользователи и роли

Создаются в разделе **Администрирование** (`/admin/`) → Пользователи. Новый пользователь получает
роль «Сотрудник»; другую роль, подразделение, должность и телефон задают в «Профили».
Суперпользователь всегда считается администратором.

| Роль | Что может |
|---|---|
| Сотрудник | Создает заявки (в т.ч. по QR), видит только свои заявки и закрепленную за ним технику, смотрит «Что где стоит» |
| Оператор | Принимает заявки, назначает исполнителя, ведет реестр оборудования, импорт, наклейки |
| Инженер | Видит все заявки, меняет статус, пишет решение (оно попадает в базу решений) |
| Руководитель | Все, что оператор и инженер, плюс отчеты |
| Администратор | Все, плюс раздел «Администрирование» (если отмечен «Статус персонала») |

## Заполнение реестра

1. **Оборудование → Импорт из Excel** → «Скачать шаблон». Заполните таблицу (можно в Excel,
   сохранить как .xlsx или «CSV (разделители — точка с запятой)») и загрузите.
   Повторная загрузка обновляет карточки по инвентарному номеру.
   То же из командной строки: `python manage.py import_equipment реестр.xlsx`.
   **Сбор данных с компьютеров автоматически:** `deploy/inventory/collect_pc.ps1` на каждом
   Windows-ПК дописывает строку (имя ПК, IP, MAC, модель, серийный номер, ОС, список программ)
   в общий CSV, который потом загружается через импорт:
   `powershell -ExecutionPolicy Bypass -File collect_pc.ps1 -Out \\SRV-01\inventory\pcs.csv -Inventory PC-205-014 -Room "Кабинет 205" -Employee "Петрова Елена"`
2. Чтобы в колонке «Сотрудник» техника сразу закрепилась за человеком, сначала заведите пользователей.
   Если пользователь не найден, имя попадет в «Примечание».
3. **Оборудование → QR-наклейки** → выбрать кабинет → «Печать». Наклеить на технику.
4. **Оборудование → CSV** — выгрузка всего реестра (тот же формат, что у импорта).

## Уведомления на почту

Заполните в `.env` `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`
(для Яндекс/Mail.ru нужен «пароль приложения») и укажите e-mail у пользователей.
Оператор/инженеры получают письмо о новой заявке, исполнитель — о назначении, автор — о смене статуса.

## Настройки `.env`

| Переменная | Значение |
|---|---|
| `DJANGO_DEBUG` | `0` для работы в сети |
| `DJANGO_SECRET_KEY` | длинная случайная строка (создается `make_env.py`) |
| `DJANGO_ALLOWED_HOSTS` | IP и имя сервера через запятую |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | те же адреса с `http://` и портом |
| `PUBLIC_BASE_URL` | адрес для QR-кодов, например `http://192.168.1.10:8000` |
| `SHOW_DEMO_LOGINS` | `1` — показать демо-пароли на странице входа |
| `TECHDESK_PORT` | порт, по умолчанию `8000` |
| `POSTGRES_DB` | пусто — SQLite; заполнено — PostgreSQL |
| `EMAIL_HOST` и др. | почта для уведомлений; пусто — не отправлять |
| `LOGIN_MAX_FAILURES`, `LOGIN_LOCKOUT_MINUTES` | блокировка подбора пароля (по умолчанию 5 попыток, 15 минут) |
| `DJANGO_ADMIN_URL` | адрес админки, по умолчанию `admin/` |

Если сменился IP сервера — исправьте его в `.env` (4 места) и перезапустите сервер.

## Если не открывается

| Симптом | Причина и решение |
|---|---|
| С сервера открывается, с других ПК — нет | Брандмауэр: `open_firewall.bat`; сеть Windows должна быть «Частная» |
| `Bad Request (400)` | Адреса нет в `DJANGO_ALLOWED_HOSTS` |
| `CSRF verification failed` при входе | Адреса нет в `DJANGO_CSRF_TRUSTED_ORIGINS` |
| Страница без оформления | Не выполнен `python manage.py collectstatic --noinput` |
| QR с телефона не открывается | Телефон не в офисном Wi-Fi или неверный `PUBLIC_BASE_URL` |
| `ImproperlyConfigured: ... DJANGO_SECRET_KEY` | Не создан `.env`: `python deploy/make_env.py` |

## Безопасность

Сайт работает по HTTP внутри офиса — это допустимо для пилота. Не пробрасывайте порт 8000
в интернет через роутер: для доступа извне используйте VPN или HTTPS ([INTERNET.md](INTERNET.md)).
